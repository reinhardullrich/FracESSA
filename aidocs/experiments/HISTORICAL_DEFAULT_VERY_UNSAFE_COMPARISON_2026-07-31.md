## Method

- All benchmarks were pinned to CPU 2. Every mode except Werner exact measured all 87 retained canonical matrices.
- Current unsafe, verified, and exact used the same Release/native/LTO Pybind binary with algorithm revision [34e003168607](https://github.com/reinhardullrich/FracESSA/commit/34e003168607a6e4f0ebbc6a949b717c86c5f1c3). Its only additional working-tree source change made MatrixParser header-only, outside the native timer.
- Historical default, very unsafe used raw-double algorithm revision [32f61679da64](https://github.com/reinhardullrich/FracESSA/commit/32f61679da64beb30f36870e190538f9d80e5970). Its temporary Pybind adapter only selected the normal parser and changed the timer from microseconds to steady-clock nanoseconds.
- Werner very unsafe and Werner exact used the backed-up 19 November 2016 release whose algorithm sources match [`zzz_legacy/REF_2016-11-20-Werner`](../../zzz_legacy/REF_2016-11-20-Werner). Its temporary adapter changed only result delivery and nanosecond timing; parsing remained outside the native timer.
- Each complete non-Werner-exact mode kept its native module loaded in one Python process. Werner exact was restarted after skipped matrices; after the two-minute rule was introduced, each remaining matrix ran in a separately supervised wrapper. Python startup is outside the returned C++ duration.
- For each matrix and mode, the first returned C++ duration selected ceil(1 second / first duration) total samples and remained part of the sample. A duration at or above one second selected one run.
- The stored and displayed result is the median of the returned C++ `elapsed_ns` samples. Python wall time is metadata only and does not select or determine the reported timing.
- Werner exact was attempted only when current exact took at most 30 seconds. IDs 33, 45, 47, 55, 63–66, and 89–90 were therefore not attempted.
- Werner exact IDs 32, 34, 52, 62, and 70 exceeded two minutes and were stopped without storing a row. The other 72 rows completed and matched their expected ESS counts.
- Times below are native medians converted from nanoseconds to microseconds. An em dash means Werner exact was skipped.
- Very unsafe Δ vs unsafe = (historical default very unsafe time / unsafe time - 1) × 100%.
- Very unsafe Δ vs verified = (historical default very unsafe time / verified time - 1) × 100%.
- Negative percentages mean historical default very unsafe is faster than the comparison mode.
- An asterisk marks an incorrect ESS count. Historical default very unsafe and Werner very unsafe are wrong on IDs 38–39; current unsafe is wrong on IDs 45–47; verified, current exact, and all recorded Werner exact rows are correct.
- The historical revisions predate the current support-generator redesign, so these are whole-version comparisons, not isolated normalization comparisons.
